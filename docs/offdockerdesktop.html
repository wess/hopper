Move off Docker Desktop

Bring your images and containers across, then uninstall the thing you were paying for.

Hopper Engine is a Docker-compatible Linux VM managed by Hopper. It supports the Docker CLI, Compose, image builds, named volumes, bind mounts, restart policies, published localhost ports, and tools that use the Engine API. Docker Desktop is not required.

1. Take stock

With Docker Desktop still running, open Hopper. It will connect to it — the footer says Connected to Docker ….

Note what you actually need. docker ps -a, docker images, docker volume ls. Most people find half of it is scratch.

2. Start Hopper Engine

Open Settings → Which engine → Hopper Engine. Hopper downloads its verified VM support files on first use and starts the engine. Your home directory is shared for bind mounts and published ports are forwarded to localhost.

Leave Keep the engine running after closing Hopper enabled so terminal and CI workloads continue when the window is closed.

3. Set up the Docker CLI

Under Settings → Docker CLI, click Install Docker CLI tools. Hopper installs its bundled Docker, Compose, and Buildx commands for your user, activates a Docker context named hopper, and migrates Docker Desktop's credential-store setting to the macOS Keychain helper so pulls and logins keep working after Desktop is removed.

docker version
docker compose version
docker buildx version
docker run --rm hello-world

4. Move the workloads you need

Images can be pulled again from their registries. Recreate Compose projects with docker compose up -d. For irreplaceable local images, save while Docker Desktop is active and load after switching to Hopper Engine:

docker save my-image:tag -o my-image.tar
# switch to the hopper context
docker load -i my-image.tar

Copy important named-volume data before removing Docker Desktop. Docker Desktop and Hopper Engine use separate VM disks, so uninstalling one does not migrate the other.

5. Verify before uninstalling

Start each Compose project, test its ports, run an image build, and confirm the data you care about. Quit Hopper once and verify that docker ps still works.

6. Uninstall Docker Desktop

/Applications/Docker.app/Contents/MacOS/uninstall

Hopper's CLI and hopper context remain available. Docker Desktop's old desktop-linux context can be removed later with docker context rm desktop-linux.

Current boundaries

  • Hopper Engine currently supports Apple silicon Macs running macOS 26 or later.
  • The VM shares your home directory by default. Add other host paths in Settings before using them as bind mounts.
  • Tools hardcoded to /var/run/docker.sock need configuration to use the Hopper context or its socket path.
  • Back up important volumes independently. A local VM disk is not a backup.
